# GitHub Actions の使い方

## 目的

このリポジトリでは、GitHub Actions の標準ランナーを使い、上流ソースの参照先とプロジェクト文書を自動確認します。**現時点では Android 17 AOSP 全体のビルドは行いません。**

## なぜフルビルドしないのか

GitHub Actions の標準 Linux ランナーは、一般的なAOSPビルドに必要なメモリとディスク容量を満たしません。AOSP公式のビルド要件を確認したうえで、必要なリソースを確保できる環境が用意できたらフルビルドを別途検討します。

## 自動チェックの内容

`.github/workflows/upstream-check.yml` は、次の内容を確認します。

- 必須のプロジェクト文書が存在し、空ではないこと。
- Raspberry Vanilla の Pi 5 デバイス設定、ローカルマニフェスト、カーネルマニフェストに `android-17.0` ブランチが存在すること。
- Android 17 用ローカルマニフェストのURLからファイルを取得できること。

このチェックが成功しても、AOSPがビルドできること、ROMが起動すること、TWRPやKernelSU Nextが動作することを意味しません。

## 実行方法

1. リポジトリの **Actions** タブを開きます。
2. **Android 17 upstream checks** を選びます。
3. **Run workflow** から手動実行できます。
4. 実行結果とログを確認します。

mainブランチへのpushやPull Requestでも自動実行されます。

## フルビルドを再検討する条件

- AOSPの要件を満たすCPU、RAM、空きディスク容量があること。
- ソースの取得先、ブランチ、ライセンスを確認済みであること。
- ビルドに必要な時間と、生成物を保存する方法を確保できること。

ビルド用環境が用意できるまでは、ソース調査、設定の理解、文書の整備、自動チェックを進めます。
